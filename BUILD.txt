Bud&Leaf v7b - experimental local-first Firebase sync

Base:
- v7a identity checkpoint
- rollback branch: v7a-identity-checkpoint

WHAT THIS CHECKPOINT DOES
- keeps all existing local IndexedDB/project-folder saving
- adds optional Firebase connection using the user's own Firebase project
- uses anonymous Firebase Authentication for this prototype
- lets a project be cloud-enabled or remain local-only
- syncs project metadata and survey features by project_uuid / feature_uuid
- receives collaborator-created features through a live Firestore listener
- sends local edits back to Firestore
- carries deletion tombstones so deleted features can be removed on collaborators' devices
- lets another device browse/open projects in the same Firebase backend
- shows Surveyor provenance when a feature is opened
- keeps .bud / ZIP backup/export unchanged

NOT IN THIS CHECKPOINT
- production invitation / membership permissions
- Google/email sign-in
- photo upload/sync
- robust concurrent-edit conflict UI
- cloud-provider abstraction beyond the first Firebase adapter

TEST INTENT
1. Prove Bud&Leaf still works completely locally without Firebase.
2. Connect one Firebase project on Phone A.
3. Enable cloud for a Bud&Leaf project.
4. Connect the same Firebase project on Phone B.
5. Open the cloud project on Phone B.
6. Add different T/G/H/W records on both phones.
7. Confirm records appear on the other phone after connectivity returns.

IMPORTANT
This is a development checkpoint only. Use authenticated-test Firestore rules while testing.
Do not use permissive public Firestore rules for production.
